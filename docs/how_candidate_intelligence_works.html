The Core Transformation

Why old systems fail, and why intelligence wins.

Traditional Keyword Search

Matches exact words typed into a search box.

  • ✕ Misses great candidates if they say "TypeScript Lead" instead of "Frontend Engineer".
  • ✕ Creates messy duplicate profiles when a candidate uploads a slightly tweaked resume.

Concept Intelligence

Understands the meaning of a resume.

  • ✓ Recognizes that "TypeScript Lead" and "Frontend Engineer" live in the same neighborhood of skills.
  • ✓ Automatically blocks exact duplicate files instantly before they clog up the system.

The Upload Pipeline

What happens the moment you drag-and-drop a resume.

1

Preventing Duplicates

Before reading a single word, the system takes a unique "digital fingerprint" of the file. If that exact file was already uploaded, it stops immediately. No more duplicate records from the exact same PDF.

Under the Hood: Fingerprinting

We use SHA-256 CAS (Content Addressable Storage). It generates a cryptographic hash of the document bytes. If the hash exists in our SQLite WAL database, we skip re-parsing completely.

2

Rule-Based Extraction

The system carefully reads the document layout and tries to extract the candidate's Name, Email, Phone, and Job Title using strict formatting rules. It then calculates a "confidence score" based on how sure it is about these facts.

Under the Hood: Tier 1 Parsing

We utilize PyMuPDF for layout parsing, alongside regex and spaCy NER (Named Entity Recognition). The system calculates a confidence score weighted heavily by the presence of a clear Name (50%), Job Title (25%), and Skills/Location (25%).

3

AI Fallback Recovery

If the system is less than 70% confident about the candidate's details (or if a key piece like Job Title is missing), it hands the text over to a local AI. The AI acts like a human recruiter, reading the messy text to infer the missing details.

Under the Hood: Local LLM Extraction

If the Tier 1 confidence is < 0.70, it triggers extract_inferences(). This sends the text to a local Ollama LLM. The LLM parses the unstructured text and guarantees 100% data privacy because the AI runs entirely on your local machine.

4

Profile Linking

It scans the extracted contact info (emails, phone numbers). If it spots "alex@example.com" and Alex is already in your database, it neatly attaches this new resume version to Alex's existing candidate card.

Under the Hood: Entity Resolution

SQLAlchemy models automatically check for collisions on standardized email and phone fields. Resolving entities early keeps the candidate table clean.

5

Building the Idea Map

Finally, the resume is chopped into logical chunks. The AI reads each chunk and plots it on a giant, invisible 3D map of concepts. Related skills sit close together on this map.

Under the Hood: Vector Embedding

We use SentenceTransformers / FastEmbed to convert text chunks into numerical vectors. These are stored locally in a LanceDB vector database, allowing for ultra-fast semantic proximity searches.

The Search Pipeline

How we guarantee exact matches while ranking by semantic fit.

1

The Job Ad Distiller

If you type a short search (like "Python Dev NY"), it skips this step. But if you paste an entire job advertisement into the search box, the local AI intercepts it. It reads the whole ad and pulls out exactly what matters: the role, must-have skills, minimum years of experience, and location.

Under the Hood: AI Job Ad Distillation

If a query is > 350 characters, it triggers the distill_job_ad() pipeline. It uses a local Ollama Chat Model to extract a structured JSON recipe (title, skills, min_yoe, location). If the AI fails, a heuristic fallback uses regex to extract years of experience and keyword frequency counting.

2

Engine A: Strict SQL Filters

The system applies the hard rules first. If the Job Ad Distiller found "Location: NY" or "Years of Experience: 5+", it completely filters out anyone who doesn't meet these baseline requirements.

Under the Hood: Relational Filtering

Standard SQL Filtering via SQLAlchemy on structured relational database columns to guarantee 100% accuracy on strict constraints.

3

Engine B: Semantic Proximity

For everyone left, the "smart" engine takes over. It compares the meaning of your search against the candidate's "Idea Map". It knows that someone with "AWS" and "Kubernetes" is a great match for a "Cloud Expert" search, even if they didn't use those exact words.

Under the Hood: Vector Search

Vector Semantic Distance calculation in LanceDB. It compares the dense embedding vector of the search summary against the stored chunk vectors.

4

Hybrid Fusion Scoring

The system combines the exact keyword hits with the soft semantic meaning to give every candidate a final "Match Percentage". You get a ranked list of the absolute best fits instantly.

Under the Hood: Hybrid Ranking Fusion

This is Hybrid Search. A fusion algorithm (like Reciprocal Rank Fusion) fuses the sparse (keyword) and dense (vector similarity) scores into a final unified rank.
