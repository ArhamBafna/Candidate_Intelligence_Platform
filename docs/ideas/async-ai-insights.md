# Async AI Candidate Insights

## Problem Statement
How might we provide recruiters with deep AI explanations for top candidates without slowing down the initial search experience?

## Recommended Direction
Return search results immediately using fast keyword/vector ranking. Trigger independent background AI requests to write personalized match explanations only for the Top 3 candidates using Server-Sent Events (SSE). Stream token updates to the UI in real-time, allowing recruiters to cancel generation per candidate at any point.

## Architecture & Technical Decisions

### 1. API & Transport Design
- **Endpoint**: Dedicated per-candidate rationale endpoint (e.g., `GET /api/candidates/{id}/insight?query=...` or `POST /api/candidates/{id}/insight`).
- **Concurrency**: 3 separate concurrent requests triggered by the frontend for the top 3 candidates.
- **Protocol**: Server-Sent Events (`text/event-stream`) streaming tokens directly as generated by local Ollama.
- **Payload & Context**: Search query + full candidate resume/profile text retrieved from storage to ground the match explanation.

### 2. Cancellation Lifecycle
- **Frontend**: Each candidate card provides an active `AbortController`. Clicking "Cancel AI Note" fires `.abort()`, closing the SSE connection.
- **Backend**: FastAPI / async server listens for client disconnection events. Upon disconnect, the backend immediately cancels the active HTTP stream / request to Ollama to free local GPU/CPU compute.
- **UI Fallback**: Cancelling an insight clears the loading state and renders a "Generate AI Note" button for manual re-triggering.

## Key Assumptions to Validate
- [ ] We can reliably separate the search query API from the AI rationale API.
- [ ] The UI can handle partial/streaming updates for specific candidate cards.
- [ ] The fast search is accurate enough that the Top 3 are actually the right people to write notes for.

## MVP Scope
- Search API returns ranked candidates immediately without AI rationale.
- Frontend initiates 3 independent SSE streams for the top 3 candidates.
- Frontend displays streaming markdown notes and a "Cancel AI Note" button per card.
- Backend aborts local Ollama inference on client disconnect.
- Cancelled / un-streamed candidate cards offer a manual "Generate AI Note" button.

## Not Doing (and Why)
- Not generating AI notes for all candidates — too slow and expensive on local hardware.
- Not blocking search results waiting for the LLM — destroys search latency and UX.
- Not using WebSockets — SSE is simpler, unidirectional, and natively handles streaming text.
- Not altering core search ranking logic — maintains strict isolation of the AI explanation layer.
